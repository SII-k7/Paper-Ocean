# v1.2.2 · Fast 与流式响应优化

## 更新方式

已安装 v1.2.1 Windows Setup 或 Ubuntu `.deb` / AppImage 的用户，在应用「关于 → 检查更新 → 一键更新并重启」安装本版本。便携版 Windows 和未签名 macOS 仍使用手动下载。更新保留原有资料库及同步配置。

## 新行为

- 默认优先使用 **GPT-5.6 Luna · max · Fast**。读取模型目录中的 Fast 服务档位 ID 并传给实际请求，而不是仅修改界面标签；本次验证的 Codex CLI 0.146.0 公布的是 `priority`。
- 输入框上方增加“响应速度”：可选 Fast 或标准，并随讨论保存。标准模式显式清除服务档位；目录没有 Fast 时显示标准，不冒充已加速。模型与 max 思考强度不变。
- 等待期间显示当前阶段及用时；完成后保留首字等待和总耗时。网络自动重试也会显示提示。不会展示模型的私有思考内容。
- 同一服务进程内复用已加载会话，关闭、服务退出或上下文目录变化后重新恢复。以最多 16 路并发读取论文分片；任一文件读取失败便停止发送，避免带着缺失证据回答。
- 流式显示按 50 毫秒合并更新，减少长答案排版开销；完成、停止、保存时刷新剩余文本。按消息 ID 汇总多个输出项，修复后一个完成事件覆盖前段内容的问题。稳定证据链接回调，避免已有答案随新 token 反复排版。

根据 [OpenAI 官方速度说明](https://learn.chatgpt.com/zh-Hans/docs/agent-configuration/speed)，GPT-5.6 Fast 标称约 1.5 倍模型速度，额度消耗约为标准模式的 2.5 倍。实际可用档位以账号模型目录为准；不会更改系统全局 Codex 配置。

## 测速结果与限制

2026-09-09 在同一 Windows 主机、同一账号，使用脚本生成的虚构机器人控制资料进行两组顺序测试。每组为新讨论加一次追问；文字上下文 81,488 字节、122 个分片，没有附图。两组问题一致，模型均为 Luna max。没有使用用户论文或阅读记录作为联网测速资料。

| 指标 | 原版标准档位 | Fast + 会话复用 |
| --- | ---: | ---: |
| 首问：首字等待 | 96.1 秒 | 91.8 秒 |
| 首问：总耗时 | 99.4 秒 | 94.4 秒 |
| 追问：首字等待 | 18.4 秒 | 12.8 秒 |
| 追问：总耗时 | 20.7 秒 | 14.3 秒 |

这是各一次的观测，不是平均值或稳定性能保证。首次本地准备和会话建立合计不到 1 秒，主要等待在提交后、首段回答返回前；本次 Fast 未显著改善长上下文首问。排队、网络、缓存命中、答案长度与 max 思考都会影响端到端时间，不能据此承诺达到 ChatGPT 网页相同速度，也没有用字符数冒充 token 吞吐率。额外的阅读会话插件关闭对照未明显改善首问，因此未更改插件加载策略。

本次没有缩减论文文字预算、跳过证据分片、移除页图或降低思考强度。首字时间统计从点击发送到首次刷新回答文字，包含本地准备；总耗时截止完成事件。
