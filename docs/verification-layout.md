# 桌面排版修复验证

2026-09-08。使用独立 Electron 用户目录，生产构建和公开／合成 PDF，保留原资料库。用户已确认中文输入法没有问题；本轮处理其后反馈的界面文字错位。

## 修复与原因

1. 顶部操作：文字“笔记”误用 38 px 图标按钮，标题栏为系统窗口按钮预留空间后，操作区还能被 flex 压缩，造成文字逐字换行。文字按钮改为内容宽度，操作不再收缩，由搜索栏吸收空间变化。
2. PDF 工具栏：绝对定位覆盖第一张页码标签，窄阅读栏下页码与缩放控制也没有换行空间。工具栏改为正常布局，空间不足时分行，目录与滚动区从工具栏下方开始。
3. 提问区：回答深度和模板入口缺少内边距；主提问框样式匹配了模板里的所有 textarea，覆盖模板边框与高度。缩小选择器范围，独立设置模板边框、间距及滚动高度。
4. 模型弹层：固定最小宽度 350–360 px 超过探索模式 320 px 对话栏，会被父栏裁剪。改为依对话栏宽度约束，模型和思考强度选项自动分列，弹层高度受视口限制。
5. 新回答提示：从固定 bottom 偏移改为在输入区上方参与正常排版，避免新增输入选项后盖住输入内容。
6. 浅色模式选中状态：思考强度按钮的浅色背景覆盖了选中背景，却保留白色文字。恢复绿色选中背景，并修正“完成”按钮与小标题的浅色对比度。

## 实际检查

- 1680×980、1280×800、1180×720、1024×768，均检查讨论与探索两种布局；最后一个尺寸为额外压力验证，低于桌面默认最小宽度。
- 包含“最近阅读”的完整顶部操作区，检查按钮内容无水平溢出，控件未侵入 Windows 窗口按钮预留区。
- 实际打开模型与模板弹层，检查左右边界留在对话栏内、上下边界留在视口内、选项文字未溢出按钮。
- 用键盘将阅读栏收至 360 px：工具栏自动成为两行（102 px 高），目录与 PDF 滚动区起点均在工具栏之后。
- 18 px 笔记正文：中文、粗体、行内／独立公式、表格正常显示。复核深浅色笔记、资料库、关于弹窗。
- TypeScript、生产构建以及 93 项已有自动测试通过；git diff --check 通过。未新增镜像样式实现的单元测试。
